# Proposal and Forms Writer

Most small business bids don't lose because the writing is bad. They lose because they missed one requirement, and the government tosses them before anyone reads a word. This skill builds the proposal deliberately, one checked piece at a time.

Never draft the whole proposal in one pass. Never start writing before the questions are answered.

## Step 1: Get the requirements checklist

You need the list of every "shall" and "must", and what they want submitted.
- If the Contract Breakdown skill was run in this chat, use its checklist.
- If not, ask for the solicitation files and build the checklist first (every requirement, where it's from, where it will be answered). Read every attachment and the latest amendment.

## Step 2: Ask questions first

Before writing anything, ask:
1. Company name (and DBA if different), website
2. UEI and CAGE code, and whether SAM.gov registration is active
3. Are you the prime, or a sub to someone else?
4. Subcontractor name and website, if using one, and whether to name them in the proposal or say "our team" / "a specialized partner"
5. Past work to feature: 1 to 3 jobs with customer, what you did, dollar value, dates, and a contact if available
6. Your price (or the sub's price plus your markup) if this is a priced offer
7. Any set-aside status you hold (small business, 8(a), WOSB, SDVOSB, HUBZone)

Do not fill gaps with made-up details. If something is missing, leave a clear placeholder like [PAST PERFORMANCE CONTACT] and list it back to the user.

## Step 3: Build the table of contents from the checklist

- If the solicitation says what sections, volumes or order it wants, mirror that exactly.
- If not, use at most 6 sections. A typical set:
  1. Cover letter / executive summary
  2. Technical approach (how you'll do the work)
  3. Company profile and capabilities
  4. Management and staffing plan
  5. Past performance
  6. Price (often a separate file or the SF 1449 itself)
- Next to each section, list which checklist items it answers. Every checklist item must land somewhere.

Stop and ask: "Does this table of contents look right before I start writing?" Wait for approval.

## Step 4: Write one section at a time

For each section:
1. Write it using the solicitation's own words for things (if they say "the Contractor", don't say "the vendor").
2. Be specific to this job: agency, location, scope. A reader should be able to tell it wasn't recycled.
3. Back every claim with a fact (a past job, a number, a certification). No "extensive experience" without proof.
4. Check it against the checklist and list which items it covered.
5. Ask: "Good to move on, or should I change anything?" Wait for approval.

Writing style: short, direct, active voice, clear headings, no filler. Keep within any page limit.

## Step 5: Walk through the forms, box by box

For every form the solicitation requires (most often the SF 1449 for commercial and simplified buys), go block by block:

| Block | What it's asking | What to put / who fills it | Done? |
|---|---|---|---|

How to do it:
- Read the actual form in the solicitation package and use its block numbers and labels. Versions and agency instructions vary, so the form in hand wins over memory.
- Mark which blocks the government already filled in, and which the offeror fills in.
- On the SF 1449 the offeror usually completes the contractor/offeror name and address block (with UEI/CAGE and phone), the remittance address if different, the prices in the item/schedule columns, any prompt payment discount, and the signature, printed name, title and date in the offeror signature blocks. Confirm each against the form and the solicitation's instructions.
- Point out any boxes that need an acknowledgment of amendments.
- Tell the user exactly what to sign and where, and remind them to sign it themselves.

Do the same for any other required forms (pricing sheets, past performance questionnaires, representations and certifications).

## Step 6: Final check and finished file

1. Run the whole proposal against the checklist and show a table: requirement, where it's answered, status. Flag anything missing in bold.
2. Check format rules: page limits, font, file type, file names, number of volumes.
3. Restate the deadline with time and time zone, and the submission method.
4. Assemble the approved sections into one finished Word document. List separately anything that must be submitted as its own file (signed SF 1449, pricing sheet, forms).

The user reviews, decides to bid, signs and submits. The skill does the paperwork; the user makes the decision.
